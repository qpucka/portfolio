How I Work

How I approach every build.

These come from years of building software for people who aren't software engineers.

01

Zero-training target

If someone can't pick it up in 30 seconds, I change the software — not the training.

02

Web-first, always

Everything runs in a browser. No installs, no "it works on my machine," no platform limitations.

03

Fail visibly, never silently

Systems detect broken states and say so in plain language. They never appear to work when they aren't.

04

Config belongs in data

Non-developers can update tool lists, settings, and options without touching code.

05

Ship, then improve

Something working in production teaches more than anything built in isolation. I iterate from real use.

06

Build for the user, not the builder

I measure success by whether the person using it needed a manual.
